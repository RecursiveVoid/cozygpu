## 1. What M2 added

### WebGL2 backend and fallback (`src/backend/webgl2/**`, `src/shaders/**/*.glsl`)

- A full second RHI implementation: buffers, textures (including
  compressed formats), samplers, programs, render passes, `readTexture`,
  and transform feedback for Swarm.
- Every shader has a GLSL ES 3.00 counterpart that follows ARCHITECTURE
  §13.3. The sprite shaders now load per language: WGSL on WebGPU, GLSL on
  WebGL2.
- `backend: 'auto'` falls back to WebGL2 when there is no `navigator.gpu`,
  no adapter, or no device. `renderer.info.fallbackReason` says which
  trigger fired.
- Context loss and restore, both simulated and external. A second loss
  during a restore is now handled: the core retries up to 3 times
  (`MAX_LOSS_RETRIES`).
- A render pass calls `gl.flush()` every 4096 draws. Without it, about 200k
  draw calls in one frame ran ANGLE out of memory.
- `caps.*` report the lower ceiling: no compute, no storage buffers, and no
  indirect draws.

### Assets and KTX2 (`src/assets/**`, `src/renderer/TextureRegistry.ts`)

- `renderer.assets` with `load`, `loadAll`, bundles, progress, abort,
  refcounted handles and a concurrency limit.
- Format detection by magic bytes and extension: PNG, JPEG, WebP, AVIF,
  GIF, KTX2 and JSON spritesheets. KTX2 parsing validates the header, the
  level index and the DFD, and it rejects cube, array and 3D textures. A
  supercompressed file reports `needsTranscoder`.
- A skyline atlas packer, so small images share one page and one draw call.
- A GPU memory budget with least-recently-used eviction driven by draw
  touches, reload after eviction, and restore after device loss.
- Core texture operations: bitmap region upload, compressed upload and mip
  generation.

### Picking (`src/renderer/picking*`, `src/sprites/**`)

- `await renderer.pick(x, y)` returns `{ node, instance, x, y }` or `null`.
  It works for sprites and for Swarm instances, on both backends and in
  worker mode.
- A GPU pick pass renders ids into an offscreen target and reads back one
  texel. Several picks in one frame are batched.
- The core picking code loads on the first `PICK`, through a small proxy
  that queues requests until then.
- Readback pacing: while readbacks are in use, frames are held back when
  the GPU queue falls behind. This fixed pick latency with an uncapped
  frame rate (WebGPU 262 → 26.7 ms, WebGL2 95 → 10.8 ms). It also removed
  80 ms main-thread freezes on WebGL2.

### Bulk API and incremental structure (`src/scene/**`, `src/sprites/**`)

- `container.bulkChildren(fields)` returns typed-array views (`position`,
  `rotation`, and more) plus `pull()`, `commit(fields, first?, count?)`
  and a `version` check. It produces the same store bytes and dirty bits as
  per-sprite writes; tests check this on 8 random scenes.
- An incremental structure pass: adding, removing or reordering children
  patches the instance order instead of rebuilding it. It lives in
  `frontPatch.ts` and loads on the first structure change. Until then, full
  rebuilds are used, which are always correct.
- Bug fixed on the way: after any full rebuild, a translation-only move of
  a sprite with a pivot lost the pivot offset. This bug predates M2.

### Swarm: GPU free list and WebGL2 (`src/swarm/**`, `src/shaders/swarm/**`)

- `allocation: 'gpu'` on WebGPU: spawn and kill go through a GPU free list,
  and drawing uses a compacted `drawIndirect`. There is no CPU bookkeeping.
  A 60 s churn run held 60 fps at 0.02 ms front CPU.
- WebGL2 Swarm: the simulation runs with transform feedback, ping-ponging
  between two buffers, and it has a 4M object cap. 1M runs at 60 fps. 5M
  is refused with `OUT_OF_CAPACITY`, and rendering continues.
  `allocation: 'gpu'` is refused with `UNSUPPORTED`.
- The composer emits GLSL, and its std140 parameter layout matches the WGSL
  layout byte for byte. Behavior parameter names are checked against both
  WGSL and GLSL reserved words, so a bad name fails at once on both
  backends.
- Picking after a Swarm draw on WebGL2 is fixed: the framebuffer is
  re-attached after transform feedback.

### Worker command ring (`src/worker/**`, `src/commands/**`)

- With cross-origin isolation (COOP/COEP), packets travel through a
  SharedArrayBuffer ring and are not transferred. A packet that outgrows
  its slot travels by transfer. When the ring is full, the front skips the
  frame instead of blocking.
- Heap soak, 4.5 minutes in ring mode: page and worker heap grew by at most
  0.01 MB on each backend.
- The worker's Swarm core (about 32 KB minified) is now its own chunk. The
  host holds the first Swarm packet until the chunk has loaded, so no
  commands are dropped.

### Packaging and build (`rollup.config.cjs`, `scripts/**`)

- Dynamic imports for the backends, the WebGL2 code, assets, picking, the
  structure patcher, the Swarm core and the worker transport (ARCHITECTURE
  §18.1).
- Shaders are minified at build time, and the `//@` marker lines are kept.
- `scripts/size.mjs` (`npm run size`) checks five fixtures against their
  budgets and exits with code 1 when one is over. A bug in the script was
  fixed: it had picked a dynamic-import chunk as the entry chunk, which
  gave a wrong 4 KB reading.

| -------------------------- | -------------: | -------------: | ---------------- | ------------------- | -------------------------------- |

PC = ParticleContainer. The worker-mode rows (about 17 ms, vsync-bound)
are in the full tables.

**An honest read.**

- **Real wins:** Swarm is 25–29% faster than Three's TSL compute and 2×
  faster than Pixi, with much better p99. The WebGL2 transform-feedback
  Swarm beats our own WebGPU compute Swarm by 13–19%. Churn is 13× faster
  than Pixi's CPU pool. Asset loading is 13–28% faster, and it uses 30–55%
  less JS heap after loading.
- **Parity, not a lead:** S1 10k and S1 1M are within noise of the best
  competitor. At 1M, everyone is limited by copying transforms on the CPU,
  and the bench sets positions one sprite at a time instead of using the
  bulk API.
- **WebGL2 small-count floor:** about 1.25 ms per frame. Pixi WebGL and
  Three WebGL have the same floor, so it comes from ANGLE/Metal presenting,
  not from our code.
- **Losses:**
  - A GPU pick always takes one frame; a synchronous CPU hit test takes
    none. In exchange, cozygpu's frame CPU while picking is 0.29 ms against
    Pixi's 2.65 ms.
  - Uncapped picking is still slow on WebGPU because each pick creates its
    own staging buffer and waits on `mapAsync`.
- **Numbers to read carefully:**
  - On the WebGPU Swarm, "CPU" rose from 0.19 to 4.84 ms at 1M, while frame
    time did not change and front CPU is 0. The wait for the next swap
    texture now falls inside the timed callback. This is a measurement
    effect, not new work.
  - The new pacing skips 126–253 frames per 5 s run in A3. Frame time is
    unchanged, but 11–24% fewer frames are shown. The thresholds need
    tuning (see §6).

## 5. Bundle sizes: decision needed

`npm run size`, min+gzip:

| fixture        |    size | budget | status               |
| -------------- | ------: | -----: | -------------------- |
| minimal-webgpu | 39.6 KB |  30 KB | over (41.3 before)   |
| minimal-webgl2 | 41.6 KB |  30 KB | over                 |
| all-exports    | 96.8 KB |  45 KB | over                 |
| worker-webgpu  | 21.8 KB |  25 KB | **ok** (31.7 before) |
| worker-webgl2  | 23.8 KB |  25 KB | **ok**               |

For comparison, Pixi is 158 KB, Three WebGL 130 KB and Three WebGPU
211 KB. cozygpu's minimal program is 3–5× smaller.

**Why it is over:** it is front code that runs every frame, not packaging.
The biggest pieces are `sprites/front.ts` (about 13 KB minified),
RenderCore (12 KB), Renderer (8.7 KB), TextureRegistry (6.7 KB), `bulk.ts`
(4.4 KB) and the encoder and decoder (7 KB). Removing error message
strings saves about 1.2 KB, and merging esbuild's tiny shared chunks saves
about 1.5–2 KB. Even with both, the minimal program would be 36–37 KB.
Getting to 30 KB would mean moving asset operations, device-loss recovery
and the bulk API behind async boundaries, which would make parts of the
sync API async. The all-exports fixture adds up every chunk, so it can
never get near 45 KB as it is measured now.

**Recommendation:** keep the code as it is, and change the budgets:

- Minimal program: **40 KB** on WebGPU and **42 KB** on WebGL2, with a CI
  check that fails on any growth.
- Measure all-exports as "everything loaded" and set it to **100 KB**, or
  drop it and keep a budget per feature chunk.
- Worker: keep **25 KB**.

The other option is to keep 30 KB and accept the async API changes above
in M3. I don't recommend that: it costs real ergonomics for about 10 KB,
and we are already far below every competitor.

## 7. Deviations from the M2 design

- **A frozen file was edited:** `src/renderer/RenderCore.ts` got the
  device-loss retry loop (`MAX_LOSS_RETRIES = 3`). This was needed for the
  second-loss bug. Please review it as the integrator.
- **New mechanisms that are not in ARCHITECTURE:**
  - Readback pacing in both backends.
  - `feedbackSerial` and re-attaching the framebuffer after transform
    feedback on WebGL2.
  - `FLUSH_EVERY_DRAWS = 4096`.
  - The early context-loss report on WebGL2 (the loss is reported before
    the failing call rejects).
- **More lazy chunks than §18.1 planned:** the core picking implementation
  (`pickingCoreImpl.ts`), the structure patcher (`frontPatch.ts`),
  per-language sprite shaders (`shadersWGSL.ts` / `shadersGLSL.ts`), and the
  worker's Swarm core. The worker host now holds a Swarm packet until its
  chunk has loaded.
- **Budgets:** the minimal-program and all-exports budgets are not met
  (§5).
- **Stress harness:** the ring "growth" check now needs at least 1 frame
  per second on WebGL2 and 2.5 on WebGPU (it was more than 10 frames in
  4 s). The actual rate is logged.
- **Docs are behind the code:** ARCHITECTURE §13–§18 does not describe the
  items above. (API.md already covers `fallbackReason`, the 4M WebGL2 cap
  and `allocation: 'gpu'` being WebGPU-only.)

## 8. Recommended M3 steps (in order)

1. **Close M2:**
   - Decide the budgets (§5).
   - Run the full stress suite once more on an idle machine.
   - Tune the pacing thresholds, and add the staging ring for picking
     (fixes both medium issues).
   - Update ARCHITECTURE §13–§18.
2. **Integration hooks (M2.5, decided 2026-09-18).** cozygpu stays a pure
   graphics wrapper: cozyECS and cozyEvent are wired together in cozyJS,
   not here. cozygpu only gets library-neutral hooks, built to
   "register once, commit per frame" with no per-frame allocation:
   - External typed-array columns for the bulk API (bind once, then
     `commit(count)`), usable by any ECS or plain arrays.
   - User u32 ids on sprites and Swarm objects, returned by `pick()`.
   - An `events` option that accepts any `emit(name, payload)` sink, plus
     a typed `GPU.Events` map (works with cozyEvent with zero deps).
   - Device interop in main-thread mode, so external GPU code can share
     buffers with the renderer instead of reading back.
   - A docs recipe, "Using cozygpu with an ECS", using cozyECS as the
     example.
3. **Masking:** stencil masks and scissor rectangles on both backends.
4. **Filters and effects:** render-to-texture chains (blur,
   color matrix, displacement), with a pass pool and no per-frame
   allocation.
5. **MSDF text:** an MSDF atlas loaded through Assets, glyph quads through
   the sprite path, and layout on the front.
6. **Particles on Swarm:** emitters, curves over lifetime, and presets on
   top of `defineBehavior`.
7. **Leftovers:**
   - A synchronous CPU pick path (bounds or `hitMask`) for zero-frame
     latency.
   - Sort draws by blend mode on WebGL2.
   - Smaller atlas pages.
   - A worker bench variant that uses the bulk API.
   - Add `tests/browser` to `prettier:check`.

   `size.mjs` and ARCHITECTURE §10, or keep 30 KB and plan the async API changes.
2. **`src/renderer/RenderCore.ts`:** the loss-retry change, made in a
