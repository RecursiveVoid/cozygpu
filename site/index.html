WebGPU first · WebGL2 fallback · graphics only

Millions of objects on the GPU, in a few dozen kilobytes.

cozygpu is a small 2D rendering library with a Pixi-like scene graph and Swarm, which simulates and draws millions of objects without the CPU touching them. It runs on the main thread or in a worker with the same API, and has zero runtime dependencies.

  • WebGPU, then WebGL2
  • Sprites · Swarm · Particles
  • Vector graphics
  • MSDF text
  • Filters & masks
  • Worker mode
  • 0 dependencies

What is in the box

Scene graph

Containers, sprites and textures with a familiar API. Sprites batch into one draw per texture, and bulk writers or bound typed-array columns move 100k of them per frame.

Graphics

Rects, circles, arcs, lines, curves and paths with holes, in a Pixi-style API. Simple shapes are drawn analytically, one small instance each; paths are tessellated once and shared.

Swarm

GPU-resident objects with composable behaviors: velocity, gravity, attractors, bounds, or your own WGSL/GLSL. Compute on WebGPU, transform feedback on WebGL2.

Particles

Emitters, presets and over-life curves built on Swarm. An emitter costs one spawn command per frame, however many particles it keeps alive.

Text

MSDF fonts that stay sharp at any size, wrapping and alignment, plus a Canvas2D path for any installed font. Glyphs batch with your sprites.

Filters & masks

Blur, glow, color matrix and custom filters on a Group. Masks pick the cheapest path that is exact: scissor, stencil or alpha.

Assets & picking

PNG, WebP and compressed KTX2 textures, atlases and bundles. GPU picking returns the exact node under the pointer, following each shape's real outline.

Worker mode

Move the whole GPU side into a worker with one option. The scene stays on the main thread; frames travel as a compact command stream.

Headline numbers

From the repository's benchmark suite (runs m25-final, 19 September 2026, and m4-graphics, 7 October 2026). Lower is better in every chart; cozygpu is highlighted.

117.5 fps 1M-object Swarm, WebGL2
0.10 ms CPU per frame at 1M objects
60.4 KB JS loaded, min+gzip (WebGPU)
5.65 ms frame at 1M spawn/kill churn (Pixi: 67.74 ms)

Test machine: Apple M4, 16 GB, macOS (darwin 27.0.0, arm64), Apple GPU via Metal 3; Google Chrome 153.0.8010.48 (headless, vsync and frame-rate limit off); 1280×720 canvas at 1×. Each case: 2 s warm-up, 5 s measured, fresh browser, three interleaved runs, median reported. Frame time is the interval between animation frames, so it includes GPU back-pressure. Compared against pixi.js 8.20.1 and three 0.186.0. Full tables: benchmarks/results/m25-final.md.

Get started

import * as GPU from 'cozygpu';

const renderer = await GPU.createRenderer({
  canvas: document.querySelector('canvas'),
  backend: 'auto', // WebGPU, else WebGL2
});

const swarm = new GPU.Swarm({
  capacity: 1_000_000,
  shape: 'circle',
  blendMode: 'add',
  behaviors: [
    GPU.behaviors.velocity(),
    GPU.behaviors.bounds({ x: 0, y: 0, width: 800, height: 600, mode: 'bounce' }),
  ],
});
renderer.stage.addChild(swarm);
swarm.spawn(1_000_000, {
  x: [0, 800],
  y: [0, 600],
  speed: [10, 60],
  angle: [0, 6.28],
});

GPU.ticker(renderer);

The README covers the API, worker mode and the examples; every demo above links to its full example in examples/.

* Worker mode on this page: GitHub Pages cannot send the Cross-Origin-Opener-Policy and Cross-Origin-Embedder-Policy headers, so the page is not cross-origin isolated and SharedArrayBuffer is off. cozygpu then transfers each frame's command buffer to the worker instead of sharing a ring with it. Everything works; it is just not zero-copy here. The HUD shows "worker (transfer)" in that case.
